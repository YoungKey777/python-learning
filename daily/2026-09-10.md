## ✅ 今天学了什么

**8.5 再消化（今天最值钱的一段）**
- **异常归谁管**：异常在哪个 try 块里冒出来，就归哪个 try 管；**except 块里冒出的新异常不归这条 try 管，归外面**——表面上的"并列 vs 嵌套"是幌子，真正的分界线是"从哪个块里冒出来的"
- 实验 A / 实验 B + 嵌套判断题变体，全部亲手跑过验证 ✅；兄弟 except 接不住兄弟的上报，外层能接住
- **`ValueError: 里层出事` 这类结果什么时候出现**：到死都没人接住（三种场景：压根没 try / 接住了又裸 raise / 它成了异常链的第一段）
- `raise` 不是"调用"，是"抛出 / 上报"这个动作本身

**`from exc` 逐点问懂**
- `func()` 存在的意义：仿真"底层库抛、上层接"的真实场景
- `as exc` = 起别名（和 `import numpy as np` 是同一个 as），绑定的是**实例**；except 块结束后这个名字被 Python 自动删除
- `from` = 盖"因果章"：`__cause__`（手动盖章）vs `__context__`（自动录的"当时在干嘛"）
- `from None` 是**静音，不是删除**（旧的还在，只是不显示）

**8.6 用户自定义异常**
- `class XXError(Exception)` = 挂靠错误家族；必须（直接或间接）派生自 Exception
- 保持简单：通常只提供属性；命名以 `Error` 结尾
- 标准库实例：`json.JSONDecodeError`、`pandas.errors` 一排 `*Error`
- 没血统的类 raise 时被当场换成 `TypeError: exceptions must derive from BaseException`
- `__init__` = initialization（前后双下划线 = Python 预定的特殊名字）；实例化时 Python 先造空实例、再自动调用它，self 自动传入

**8.7 finally（无论如何都要收尾）**
- 三种结局都执行：没出错 / 被接住 / 没接住（→ **先收尾，再上抛** = 重新触发）——"先还债再报丧"
- 和 return 的两条规则：try 里 return 则 finally 先跑；**finally 里 return 会吃掉一切（连异常都静默吞掉）**——亲测输出"我被返回值顶替了"，最阴险的写法

**8.8 with（预定义的清理操作）**
- **with 就是"打包好的 finally"**：finally 是你手写收尾，with 是对象**自己带着**收尾动作（`f.close()`）——所以叫"预定义"
- 不用 with 的后果：文件"在一段不确定的时间内"开着（靠垃圾回收），大程序里就是句柄泄漏
- 实测：**with 块里抛异常，文件照样被关**（`f4.closed = True`）
- 细节彩蛋：`with ... as f` 的 f 块结束后**名字还在**（对比 8.5 学的 `except ... as e` 会被删掉）——同一个 as，两处规矩不一样

**8.9 ExceptionGroup / except\***
- 把一堆异常打包成一沓"体检报告"一次抛出（收集 → 再上报）
- **`except*` 是带星号的网**：普通 except **只出手第一张**匹配的，`except*` **每张网都过一遍**（实测两张网都出手了）
- 没人认领的部分**重新打包成新异常组继续上抛**（屏幕上多出一棵树）
- 组里必须是**实例**不是类型；3.11 才有（本机 Anaconda 是 3.10.9，跑不了）
