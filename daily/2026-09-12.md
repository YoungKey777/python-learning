### 7.1.1 格式化字符串字面值 —— 把 f-string 一次讲透

- **总纲（治"这里好乱"的那张图）**：`{}` 里**只可能出现 4 样东西** —— ① 直接算 `{x}` ② 自说明 `{x=}` ③ 换显示 `{x!r}` ④ 排版 `{x:规格}`。认全这 4 样，这一节的乱就散了
- **三个转换符**：`!r` = repr()、`!s` = str()（**等于默认，写了等于没写**）、`!a` = ascii()（**非 ASCII 字符全部转义** —— 中文会变成一串"反斜杠+u+码点"，冷门）
  - 关键澄清：**`!` 是分隔符，不是"取反"** —— 和学过的 `!=` 一点关系都没有
- **`{x=}` 完全等价于 `x={x!r}`**（实测一字不差）—— 调试时能省一行 print
- **格式规格四段骨架的澄清（本节最费解的一处，今天一次说透）**：
  - 对齐**只有 `<` `>` `^` 三个**，**没有 `-`**！
  - `+` / `-` / 空格 是**符号位**，其中 `-` 的意思是"负数才显负号" = **本来就默认这样 = 废话**
  - **意外发现：官方那个例子 `'{:-9} YES votes {:2.2%}'` 里有 1.5 个废修饰符** —— 一个是废的 `-`，一个是小于内容长度的宽度 `2`。把这两个删掉，输出**一字不差**
  - 铁证：`'{:-9}'.format('abc')` → `ValueError: Sign not allowed in string format specifier` —— **Python 自己亲口说这是 "Sign" 不是对齐**
- **位数 vs 宽度（今天最大的概念纠正）**：
  - **位数由内容说了算，宽度由你说了算**
  - 宽度是**最小宽度** —— 位数 < 格数就补空格，= 就正好，**> 也一位不少（让路，绝不截断）**
- **str() vs repr() 再确认**：8 种类型里**只有"光秃秃的字符串"不一样**；容器内部对元素用的是 repr（`str([s])` → `['Hello']`）

### 7.1.2 字符串 format() 方法 —— 扫读级，认得就行

- 老写法和 f-string 是**同一件事的两代写法**，能力几乎一样，只差两点：**值放哪**（外面 vs 坑里）+ **坑里写号码还是名字**
- 四种填坑法：空坑 `{}` 按顺序 / `{0}` 按号码（**能换顺序、能重复用**）/ `{name}` 按名字 / 位置 + 关键字混用
- ⚠️ **自动编号和手动编号不能混用** → `ValueError: cannot switch from automatic field numbering to manual field specification`（要么全空坑，要么全写号码）
- **官方自己劝你别按号码**：按号码 = 每次改动都要**重数一遍**；按名字 = 想加就加
- 传字典两种姿势：`{0[Jack]:d}`（难看，**引号还不能加**，加了会 `KeyError: "'Jack'"`）vs `**table`（推荐）
  - 🔗 回指 4.9.5：**`**table` 就是当时学的"调用时 `**` 拆字典"** —— `format()` 也只是个普通函数，`**` 在哪都一样
- **本节真正要记住的一句话**：**冒号后面那一截（`:d` / `:.2f` / `:>8` / `:10`）两代写法完全相同** → **7.1.1 学的四段骨架没白学，老代码照样能用**
- 两个彩蛋认得就行、别去用：`vars()`（把当前所有局部变量打包成字典）+ 官方乘法表例子（其实是**三个不同宽度的对齐演示**，宽度刚好卡住各自最大值）

### 7.1.3 手动格式化字符串 —— 考古级，只有一样还活着

- 一句话定性：这是**没有格式规格的年代，人们怎么手动排版** —— 排版部分全被 f-string 取代了
- 官方那张平方立方表，**手动版和格式规格版输出一字不差**（本机实测确认）
- 手动版逐句拆解：`repr(x)` 是**因为 `.rjust()` 是字符串的方法，整数身上没有**（`(1).rjust(2)` → `AttributeError`）；`end=' '` 是把 print 的自动换行换成空格，好让前两列留在同一行
- 官方注释点破一件事：**列之间的空格不是排出来的，是 `print()` 顺手加的**
- `.rjust()` / `.ljust()` / `.center()` 三兄弟：**不截断** —— 和 7.1.1 学的"宽度"是**同一条规矩**（宁可不齐，也不偷偷改你的数据）；真想截断得自己切片 `[:n]`
- **`.zfill()` 是三兄弟里唯一还天天用的**：左边补零，**认得正负号**（`'-3.14'.zfill(7)` → `'-003.14'`，零补在负号后面）
  - 它凭什么活下来：格式规格的补零**不认得符号**（`f'{"-3.14":0>7}'` → `'00-3.14'`，零跑到负号前面）
  - 而且格式规格对**字符串**用 `05` 是个坑：`f'{"12":05}'` → `'12000'`（字符串默认左对齐，零补到右边）—— 同样写 `05`，数字和字符串方向相反
- ⚠️ **本节的自我纠错**：我最初写"zfill 能处理非数字字符串"，实测**这是错的**（`f'{"IF2603":0>8}'` 一样出 `'00IF2603'`）。真正的区别是**符号位置**，已改正笔记

### 7.1.4 旧式字符串格式化方法（`%`）—— 最老的一代，但没死透

- 三代格式化全家福搞清楚了：**`f-string` ← `.format()` ← `%`**（从新到旧）
- 官方管它叫**"字符串插值"（string interpolation）** —— 花名，就是"把值插进洞里"
- 那个 `%` **不是求余** —— 同一个符号被借用成格式化运算符（Python 按左右两边是什么来分辨）
- **类型字母是同一批**：`%s` `%d` `%f` `%x` 就是继承给格式规格的老祖宗
- ⚠️ **它最咬人的地方：括号不等于元组，逗号才是**
  - `'%s and %s' % ('spam')` → `TypeError: not enough arguments for format string`（`('spam')` 就是个普通字符串，1 个值喂 2 个洞）
  - 但只有一个洞时反而没事：`'%s' % ('spam')` → `'spam'`
- 另外两条：`%%` 才能打出百分号本身；想重复用一个值只能重复传参（不像 `{0}{0}{0}`）
- **它没有"自动百分比"**：`f'{x:.2%}'` → `18.35%`，而 `'%.2f%%' % x` → `0.18%` —— **得自己 ×100**
- 🎯 **本节唯一必学点：`logging` 模块至今坚持用它**
  - `logging.info('拉取 %s 行情，共 %d 行', code, n)`
  - **为什么不用 f-string**：日志绝大多数时候被级别过滤掉。f-string 是"**先算完再问要不要**"，`%` 风格是"**先问要不要再算**" —— 在"大部分时候用不上"的场景，懒的那一方赢
- ⚠️ **又一处自我纠错**：我写"连着两个 `%` 能跑但难读"，实测**跑不起来** —— `'%s' % 'a' % 'b'` → `TypeError: not all arguments converted`（第一段算完是 `'a'`，里面没洞了，再喂值就是"值多了"，Python 直接翻脸）。已改正笔记

### 7.2 读写文件 —— **周一 pandas 前的最后一关** 🚪

- **借书比喻**：`open` = 取书摊桌上、`mode` = 怎么用它、`close` = 放回去、`with` = 带自动收纳的桌子、忘了还 = 桌子被占满
- **`open()` 三参数**：`open(文件名, 模式, encoding='utf-8')` —— 模式可省略（默认 `'r'`）
- **四种模式**：`'r'` 只读 / **`'w'` 只写且覆盖** / `'a'` 末尾追加 / `'r+'` 读写
  - ⚠️ **`'w'` 是本节最危险的字符** —— 它**一打开就清空**，不是等你写的时候才清
- **编码：一律写 `encoding='utf-8'`（本机必踩的坑）**
  - 实测本机 `locale.getpreferredencoding()` → **`cp936`（GBK）**，不写 encoding 就用 GBK 存
  - 同样"贵州茅台"：GBK 存 10 字节 / UTF-8 存 14 字节；拿 utf-8 去读 GBK → `UnicodeDecodeError`
  - 而且这坑**以乱码形式出现，不报错**，更难查
- **`with` 的真实威力（回指 8.8）** —— 实测：`write()` 之后不 close，**从另一个句柄读是空的**
  - 原因：`write()` 只把内容交给**缓冲区**，`close()` 才是"推最后一把"的信号
  - `f.flush()` 可以手动推；`with` 自动做好这一切**（哪怕中途报错）**
  - 8.8 学的"块结束就关" → 今天知道它在真实场景里**救的是数据**
- **文本模式 vs 二进制模式**：加 `'b'` → 读写的是 `bytes` 不是 `str`；**二进制模式不能写 `encoding`**（`ValueError: binary mode doesn't take an encoding argument`）
  - 实测：文本模式写 `'a\nb\n'` 落盘变成 `b'a\r\nb\r\n'`（Windows 把 `\n` 偷偷换成 `\r\n`）
  - 对文本文件没问题，**对 JPEG / EXE / 图片会改坏文件**
  - 口诀：**文本模式管"行"，二进制模式管"字节"**
- 关掉之后再用 → `ValueError: I/O operation on closed file.`
- 🔑 **一句话总结**：`open(文件名, 模式, encoding='utf-8')` + `with` —— 记住这个组合够用 90%
- **和 pandas 的关系**：`pd.read_csv('行情.csv', encoding='utf-8')` —— 那个 `encoding` 就是 `open()` 的 `encoding`。**这节学会了，周一 read_csv 就是"少写一半的版本"**
