## 🧠 今天攒下的

**① `*` 是逐元素，不是复制 —— 这就是 pandas"一行改一列"的底牌**

`list` 的 `*` 是**复制**（整串复读一遍）；`ndarray` 的 `*` 是**逐元素**（每个元素各自算各自的）。所以 `df["Fare"] * 1.1` 才能一个不落地把每张票价改掉 —— Series 底下就是 ndarray；底下要是 list，就得写 `for` 循环。

**顺手捡的判别招**：`list` 有逗号 `[1.2, 3.4, 5.6]`，`array` 没逗号、用空格对齐 `[ 2.4  6.8 11.2]`。跟"看内容，不看抬头"是同一类招。

**② `.shape` 是元组，不是数字**

`a.shape` 打印出来是 `(3,)` —— 那个逗号不是排版，是 Python 语法：**只有一个元素的元组必须带尾逗号**。`(3)` 在 Python 眼里就是普通括号里的 3。

**③ `shape` 里有几个数，`ndim` 就是几**

`(3,)` → `ndim=1`；`(891, 12)` → `ndim=2`。表的 shape 带两个数，因为表有**两个方向**（往下是行、往右是列）；一列脱壳后只剩一个方向，所以只有一个数。

**④ 掀开的盖子：pandas 的表 = ndarray + 标签**

`df["Age"]` 有列名、有行号，`.to_numpy()` 一脱壳，**名字和行号全被扒掉**，只剩 891 个光秃秃的数。标签是后来贴上去的皮。

**⑤ 一根数组只能有一种 dtype**

ndarray 在内存里是**等宽排列**的（每个元素占一样多的字节，一个挨一个）—— 正因为等宽，才能"一步跨到第 n 个"，这是它快的根源。代价是**全体必须同一种类型**；真混装时，它退到最宽松的 `object`（本质是存指针，什么都塞得下，但快的那部分优势丢了）。

**⑥ 那 DataFrame 凭什么一列一个类型？**

因为 **DataFrame 不是一根大数组，而是"一列一根数组"并排放**，再贴标签：

```
DataFrame = [ Age  那根 float64 数组 ]   ← 每列各自 dtype
            [ Fare 那根 float64 数组 ]
            [ Name 那根 object  数组 ]
            +  行号、列名（标签）
```

所以 `df["Age"].dtype` 是干净的 `float64`；而整表 `to_numpy()` 压成一根后，不同列必须挤进同一种类型 → 全体降级成 `object`。
