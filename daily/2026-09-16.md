### pandas **Day 2 通关** —— 选取筛选

一篇教程（[03_subset_data](https://pandas.pydata.org/pandas-docs/version/2.3/getting_started/intro_tutorials/03_subset_data.html)）三大块全跑通，脚本在 `code/pandas_day2.py`。

### 1. 选列：单括号给「线」，双括号给「表」

```python
df["Age"]           # → Series     (891,)    1 个数 = 一维
df[["Age"]]         # → DataFrame  (891, 1)  2 个数 = 二维
df[["Age", "Sex"]]  # → DataFrame  (891, 2)
```

**决定权在括号层数，不在取了几列。** `(891, 1)` 和 `(891,)` 是两个不同的东西 —— 前者是「一张窄表」，后者是「一条线」。

顺带把 Day 1 留下的疑问钉死了：**取列，长度是行数（891）；取行，长度是列数（12）。**

**dtype 四种齐了**：`int64` / `float64` / `object`（Day 1）+ **`bool`**（今天 —— 比较运算的结果只有两种可能）。

### 2. 筛行 = 造名单 → 执行名单

```python
mask = df["Age"] > 35     # ① 造名单：891 个 True/False，和原表一样长
above35 = df[mask]        # ② 执行名单：True 的行留下，整行 12 列都带上
```

**`mask` 不是被显示出来，是被拿去执行。** 它只回答「这行留不留」，**不管留哪几列**。

实跑：`(217, 12)` —— 行从 891 掉到 217，**列一根没少**。

**筛完 index 会跳号**：`1, 6, 11, 13, 15...`。实际影响：`df[0]` 拿不到东西了。

### 3. 填洞 —— 撞上去昨天的 714

```python
mask2 = df["Age"].notna()     # "这格不是洞吗？"
df[mask2].shape               # (714, 12)
```

714 —— 就是昨天 `info()` 里那行 `Age 714 non-null`。**昨天是 pandas 告诉我的，今天是自己筛出来的。**

`Cabin` 列里的洞，在屏幕上显示为 **`NaN`**。

### 4. 多重条件：`&` 不是 `and`，每个条件自己裹括号

```python
mask3 = (df["Sex"] == "female") & (df["Fare"] > 30)
df[mask3].shape      # (113, 12)
```

两个原因：

- **不能用 `and`** —— `df["Sex"] == "female"` 给的是 **891 个** True/False，不是 1 个。`and` 判不了这么多 → `ValueError: The truth value of a Series is ambiguous`
- **`&` 的优先级比 `>` 高** —— 不加括号会先算 `"female" & df["Fare"]`，字符串和 Series 当场爆炸

### 5. `loc` / `iloc` —— 两把钥匙

|  | `loc` | `iloc` |
|---|---|---|
| **行** | index 里的值（门牌） | 第几个 |
| **列** | **列名** | **第几列** |
| 例 | `df.loc[0, "Age"]` → `22.0` | `df.iloc[0, 5]` → `22.0` |

**平时不分家，一分家就翻脸** —— `above35` 的第 0 个，门牌是 1 号：

```python
above35.iloc[0, 5]      # 38.0
above35.loc[1, "Age"]   # 38.0   ← 同一行
above35.loc[0, "Age"]   # KeyError: 0   ← 门牌 0 号被筛掉了
```

**「第 0 个」≠「门牌 0 号」。**

切片规则也不一样：`loc` 两头都算，`iloc` 不含右边（跟 Python 列表一致）。

### 6. 还了昨天欠的题：文字列怎么统计

```python
df["Sex"].value_counts()
# male   577
# female 314
```

**不问「平均多少」，问「各有多少个」。** 577 + 314 = 891，对得上。

这就是 `describe()` 跳过文字列的原因 —— **文字没有平均值**。

### pandas **Day 3 通关** —— 派生新列（向量化）

一篇教程（[05_add_columns](https://pandas.pydata.org/pandas-docs/version/2.3/getting_started/intro_tutorials/05_add_columns.html)），脚本在 `code/pandas_day3.py`。

#### 1. 向量化：一列当整体算

```python
fs = df["SibSp"] + df["Parch"] + 1     # 家庭人数 = 兄弟姐妹 + 父母子女 + 自己
print(fs.shape)                        # (891,) ← 891 个一次算完
```

**一行 `for` 都没写。** 同样的活换成普通 Python 要 4 行（`for i in range(len(df))` 一个一个加）。

- **`+1` 是把自己算进去** —— 一家几口人，不能把自己漏了
- **`fs` 是没名字的** —— `fs.head()` 里**没有 `Name:` 那行**。因为 `SibSp` 和 `Parch` 名字不同，pandas 不知道该起什么名

#### 2. 新列诞生：等号左边 = 写

```python
df["family_size"] = fs                 # 表从 12 列 → (891, 13)
df["is_child"] = df["Age"] < 18        # dtype: bool
```

**这是 Day 1「默认造新的，不动原来」的例外。**

判据：**看方括号在等号哪边** —— `a = df["Age"]` 是读；`df["新列"] = ...` 是在原表上长出一列。

布尔列命名惯例：**`is_` / `has_` 开头**，一眼看出是是非题。

#### 3. `True` = 1，`False` = 0

```python
print(df["is_child"].sum())        # 113
print(df[df["Age"] < 18].shape)    # (113, 13)
```

**两条路，同一个数。** `sum()` 把 `True` 当 1 加起来 —— 求和的本质就是**数人头**。

#### 4. `pd.cut` 分箱：连续数字 → 档次

```python
df["fare_level"] = pd.cut(
    df["Fare"],
    bins=[0, 10, 30, 100, 600],            # 5 个切点 → 切出 4 段
    labels=["便宜", "中", "贵", "土豪"]
)
```

**第五种 dtype 出现了：`category`**（前四种 `int64` / `float64` / `object` / `bool`）。

```
Categories (4, object): ['便宜' < '中' < '贵' < '土豪']
                                  ↑ 它记住了顺序
```

`object` 是「一堆随便的文字」，`category` 是「**有档次的分类**」—— 那个 `<` 号是 pandas 在说它知道谁大谁小。

**对上的数**：`便宜 321 + 中 321 + 贵 181 + 土豪 53 + NaN 15 = 891` ✅

## 🕳 坑

- **`import` 被 `#` 注释掉了** → 下面用到 `pd` 就 `NameError`。Python 从上往下读，同一文件下面有 import 也救不了
- **拼写错最阴**：`tistanic.csv` ≠ `titanic.csv`。它不「看不懂」，它「**看起来对**」
- **`FileNotFoundError` 第一反应是看提示符 `PS ...` 那串**（站在哪），不是改代码
- **`NaN` 跟任何数比较，一律得 `False`** —— `Age` 列有 177 个洞，所以 `is_child.sum()` = 113 指的是「**有年龄记录** 且 <18」。那 177 个洞被静悄悄排除在外了。**筛之前先 `info()` 看有没有洞**
- **`value_counts()` 默认把洞藏起来** —— `fare_level` 四档加起来只有 876，不是 891；加 `dropna=False` 才看见那 15 个 `NaN`。**跟 `info()` 不一样：`info()` 主动报告「714 non-null」，`value_counts()` 默认闭嘴**

**学会了读报错**：从下往上读，只找**自己的文件名**。中间那一堆 `pandas/_libs/*` 是 pandas 在自言自语。

| 报错 | 什么时候 |
|---|---|
| `KeyError` | `loc` 按门牌找不到（查字典查不到） |
| `IndexError` | `iloc` 数位置越界 |
| `FileNotFoundError` | 路径或文件名不对 |
| `NameError` | 名字没定义（多半是 `import` 被注释了） |
