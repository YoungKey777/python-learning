### pandas **Day 5 通关** —— 表变形（`pivot` / `melt`）

一篇教程（[07_reshape_table_layout](https://pandas.pydata.org/pandas-docs/version/2.3/getting_started/intro_tutorials/07_reshape_table_layout.html)）。

**同一份数据能「躺」成两种形状：**

- **宽表** —— 列 = 对象（`station_antwerp` / `station_paris` / `station_london`），**横着铺**
- **长表** —— 一行一条观测记录，城市名变成**一列的值**，**竖着拉**

🔑 **长表行数 = 宽表行数 × 被摊平的列数**

### 1. `melt`：宽 → 长

```python
no2_melted = no2.melt(
    id_vars=['datetime'],                                            # 站着不动的列
    value_vars=['station_antwerp','station_paris','station_london'],  # 要被摊平的列
    var_name='station',                                               # 原来的【列名】放这
    value_name='no2'                                                  # 原来的【值】放这
)
print(no2_melted.shape)      # (3105, 3)
```

**1035 × 3 = 3105** —— 先预测了 3105，跑出来就是 3105。

**melt 出来是「按列一块块铺」的**：`antwerp` 铺完 1035 行，再 `paris`，再 `london`。

### 2. `pivot`：长 → 宽

```python
no2_back = no2_melted.pivot(index='datetime', columns='station', values='no2')
print(no2_back.shape)        # (1035, 3)  ← 不是 (1035, 4)！
```

**为什么少一列** —— `index='datetime'` 把 `datetime` 变成了**门牌**，而 **index 不占数据列的位置**（Day 1 那条规矩）。

⚠️ `pivot` 会**按字母序重排列**：`antwerp → paris → london` 变成 `antwerp → london → paris`。

**宽 → 长 → 宽转一圈，数据零损失。**

### 3. `pivot_table`：搬家 + 顺手算

### pandas **Day 6 通关** —— 合并表（`concat` / `merge`）

一篇教程（[08_combine_dataframes](https://pandas.pydata.org/pandas-docs/version/2.3/getting_started/intro_tutorials/08_combine_dataframes.html)），脚本在 `code/pandas_day6.py`。

#### 1. `concat`：物理拼接 —— 上下摞，行变多

```python
pm25 = aq[aq["parameter"] == "pm25"]     # (1825, 7)
no2  = aq[aq["parameter"] == "no2"]      # (3447, 7)

aq_back = pd.concat([pm25, no2])
print(aq_back.shape)      # (5272, 7)
```

**1825 + 3447 = 5272**，一行不差。

🔑 **`concat` 完全听你的 —— 不排序、不去重、不检查内容、不检查对不对得上。**

自己发现的证据：`pd.concat([pm25, no2])` 和 `pd.concat([no2, pm25])` 打出来**顺序不一样**。**你对它错，它也照做。**

#### 2. `concat(axis=1)`：左右拼 —— 按【行号】对齐

```python
print(pd.concat([aq[["parameter", "value"]].head(3),
                 params[["id", "name"]].head(3)], axis=1))
```

```
   parameter  value   id name
0       pm25   18.0   bc   BC
1       pm25    6.5   co   CO
2       pm25   18.5  no2  NO2
```

左边是安特卫普的 pm25 浓度，右边是大气的化学式说明 —— **两件毫不相干的事并排坐着，中间连条分隔线都没有。**

**三种拼法，对齐的依据完全不同：**

| | 按什么对齐 | 对不上怎么办 |
|---|---|---|
| `concat(axis=0)` 上下摞 | **列名** | 缺的列填洞 |
| `concat(axis=1)` 左右拼 | **行号** | 缺的行填洞 |
| `merge` | **内容（键）** | 看 `how=` |

**`concat(axis=1)` 连「键」这个概念都没有 —— 所以连「配不上」的机会都没有。** 只有 100% 确定两张表逐行严格对应时才用（比如同一个 `df` 拆出来的两半）。

#### 3. `merge`：按共同列配对 —— 就是 JOIN

```python
params = pd.read_csv('pandas/data/air_quality_parameters.csv')   # (7, 3)

merged = aq.merge(params, left_on="parameter", right_on="id")
print(merged.shape)      # (5272, 10)  ← 行不变，列 +3
```

**两边键名不同（`parameter` ≠ `id`）→ 两列都保留，内容重复。** 键名一样时可以只写 `on="列名"`。

#### 4. `how=`：配不上的怎么办 —— 四个数对上了账

把 `params` 里的 `pm25` 删掉，故意制造「配不上」：

```python
params_cut = params[params["id"] != "pm25"]      # (6, 3)

for how in ["inner", "left", "right", "outer"]:
    r = aq.merge(params_cut, left_on="parameter", right_on="id", how=how)
    print(f"{how:6} {r.shape}")
```

先把两边的家底摆出来：

```
params_cut 的 6 个键：  bc   co   no2   o3   pm10   so2
aq        的 2 个键：        no2                         pm25
                              ↑ 唯一的交集
```

| `how` | 挑谁 | 算式 | 实测 |
|---|---|---|---|
| `inner` **（默认）** | 只要交集 | 3447 | **3447** ✅ |
| `left` | `aq` 的全要 | 3447 + 1825 | **5272** ✅ |
| `right` | `params_cut` 的键全要 | 3447 + 5 | **3452** ✅ |
| `outer` | 三堆全要 | 3447 + 1825 + 5 | **5277** ✅ |

**四个数全对上了** —— Day 4 那条「**分项加起来必须等于总数**」，今天第四次派上用场。

🔑 **「丢行」和「填洞」是同一件事的两面 —— 你必须选一个。** `how="left"` 保住了 5272 行，代价是 `pm25` 那 1825 行的右边三列全变成洞：

```
  parameter  value   unit   id description name
0      pm25   18.0  µg/m³  NaN         NaN  NaN
```

**`how=` 的读法：说的是「以谁为准」。** 以后把行情表和财报表按股票代码接起来，某只票财报缺了 —— **删掉整只票，还是留着、财报那几列空着？没有标准答案，但你必须知道自己在选哪个。**

```python
aq.pivot_table(index="location", columns="parameter", values="value", aggfunc="mean")
aq.groupby(["location", "parameter"])["value"].mean().unstack()      # ← 同一个结果
```

**② `NaN` 的三种来源，今天凑齐了：**

| 来源 | 例子 |
|---|---|
| ① 测了但没记上 | titanic 的 `Age`（177 个洞） |
| ② 算式里掉出去 | Day 3 的 `pd.cut`，票价 = 0 的掉出边界（15 个） |
| ③ **压根没有这种组合** | 上面 `FR04014 × pm25` —— 巴黎那个站根本没有 pm25 这一项 |

**③ 参数名不用背。** `名字=值` 这个写法里，**等号左边是 pandas 定死的，右边是自己给的**：

| | 谁说了算 |
|---|---|
| `id_vars` / `var_name` / `aggfunc` | **pandas 定死的**，拼错就报错 |
| `'datetime'` / `'station'` / `"mean"` | **自己给的**，叫什么都行 |

而且 `_vars`（复数）是**进**、`_name`（单数）是**出**。`value_vars` 不写的话，pandas 默认把剩下的列全摊平 —— **最常用的写法只有 `id_vars` 一个参数**。


**④（Day 6）只有「分项加起来等于总数」能救命。** 今天四个 `how` 给出四个行数 —— **3447 / 5272 / 3452 / 5277** —— 全部拆开对上了账，才敢确认没搞错。Day 4 那条自检，第四次派上用场。

## 🕳 坑

**① `head()` 会骗你** —— 长表是**按块排**的，`head(3)` 只看得见第一块（Paris）。London 从第 **1099 行**才开始，`head()` 根本够不着。

> **`head()` 是「前 5 行」，不是「每类各 5 行」。** 想看全貌得用 `value_counts()` / `groupby()`。

**② 真实数据的名字是乱的** —— 同一座城市三种拼法：

| | 宽表 | 长表 |
|---|---|---|
| 安特卫普 | `station_antwerp` | `Antwerpen` ← **多两个字母** |
| 伦敦 | `station_london` | `London Westminster`（带空格） |
| 巴黎 | `station_paris` | `FR04014`（一个编号） |

**以后 `merge` 两张表，这种不一致当场翻车。**

**③ `pivot` 会重排列序** —— 转回来列的顺序变了，别默认「它还在老位置」。

**④（Day 6）`merge` 的失败方式是「沉默」** ← 今天最要命的一条

```python
aq2 = pd.read_csv('pandas/data/air_quality_long.csv')
aq2["parameter"] = aq2["parameter"].str.upper()           # 全变大写：PM25 / NO2
bad = aq2.merge(params, left_on="parameter", right_on="id", how="left")

print(bad.shape)                                          # (5272, 10) ← 形状全对
print(bad[["id", "description", "name"]].notna().sum())   # 0 / 0 / 0  ← 内容全空
```

根因只是 `PM25` ≠ `pm25` —— **差一个大小写**。

> **它不报错、不警告、不提示，只给你一张形状对了、内容空了的表。**
> **它也不检查「这两个名字说的是不是同一件事」—— 只做字符串比对。差一个空格、一个大小写、一个复数 `s`，就是两个东西。**

**所以 `merge` 完必须查三样：**

| 查什么 | 看的是 | 这次揪得出来吗 |
|---|---|---|
| `.shape` | 行数列数对不对 | ❌ 全对，照样是废的 |
| `.head()` | 里面长什么样 | ⚠️ 能看见，但只有前 5 行 |
| **`右表某列.notna().sum()`** | **到底配上了几行** | ✅ 就是它揪出来的 |

**⑤（Day 6）洞在哪边，就说明哪边没有** —— 左边空 = `aq` 里没这行；右边空 = `params` 里没这行。**看见一片洞，先顺着洞的方向问：是哪张表缺东西？**

**⑥（Day 6）今天这场困惑，根源是 `.shape` 和 `.head()` 只打了一个。**

「`params_cut` 明明删了 pm25，怎么打印出来还有 pm25」—— 两个原因叠在一起：

- `params` 有 **7 行**，`.head()` 只给 **5 行**，**正好把 `pm25` 和 `so2` 藏了**（Day 5 那条「`head()` 会骗你」，隔一天又撞上）
- 看见的 pm25 来自**上一个** `merged`（用的完整 `params`），不是 `lost` —— 两个变量、两次 print，输出串台了

> **`.shape` 说变了多少，`.head()` 说变成了什么样。两个都打。**
